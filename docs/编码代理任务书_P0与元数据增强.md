## 3. Phase A：模型 P0 优化

### A1. 集中式模型适用性预检

新增独立服务函数，例如：

```python
assess_model_compatibility(
    image: dict,
    processed_meta: dict | None,
    model: dict,
) -> dict
```

返回结构至少包含：

- `status`: `compatible`、`warning`、`incompatible`
- `errors`: 硬性阻断原因
- `warnings`: 可确认后继续的原因
- `crop_match`: `match`、`mismatch`、`unknown`
- `sensor_match`: `match`、`mismatch`、`unknown`
- `required_bands`: 模型输入波段数
- `exact_bands`: 完全位于影像范围且无需插值的波段数
- `interpolated_bands`: 需要插值的波段数
- `edge_filled_bands`: 需要边缘填充的波段数
- `source_range`、`target_range`
- `recommendation`: 中文处理建议

兼容性规则：

- 模型文件缺失：硬阻断。
- 模型输入类型不支持：硬阻断。
- 模型要求的波段在当前影像中完全无法获得：硬阻断。
- 作物不匹配：警告，用户确认后可继续。
- 传感器类型不匹配：警告或硬阻断，按证据强度决定。
- 边缘填充比例较高：警告；比例阈值可配置。
- 元数据缺失：标记 `unknown`，不得误判为匹配。

### A2. 单幅和批量反演接入预检

- 单幅反演 API 返回或执行同一套兼容性检查。
- 批量反演开始前逐幅返回兼容性表。
- 默认拒绝 `incompatible` 影像。
- 新增显式 `force: bool = false`，只有前端二次确认后才允许忽略警告。
- 批量接口不得只检查当前界面显示的一幅影像。
- 结果摘要记录是否使用 `force`、被忽略的警告及边缘填充数量。

### A3. 前端模型选择体验

- 模型卡片显示“推荐、可重采样、不兼容、信息不足”状态。
- 当前影像切换时自动重新计算推荐模型。
- 若已选模型在新影像上不兼容，弹窗要求重新选择或明确确认。
- 批量反演弹窗显示逐影像预检表。
- 不得依赖前端警告作为最终安全边界，服务端必须重复校验。

### A4. 单位与阈值一致性

- 结果概览、图例、像元查询、直方图、统计表、趋势图、PNG 和 PDF 全部使用模型或结果的实际单位。
- 删除结果页和报告中的硬编码 `mg/g`。
- 自定义模型导入表单增加低氮、高氮阈值。
- 阈值图例必须始终显示单位。
- 对缺少单位的自定义模型给出待确认提示。

### A5. 结果追溯

模型导入成功后计算并保存模型文件 SHA-256。结果摘要至少记录：

- 模型 ID、名称、版本、算法和文件哈希
- 完整训练波长
- 本次影像波段范围
- 重采样与边缘填充统计
- 预处理配置摘要
- 是否强制忽略兼容性警告
- 本次使用的单位和阈值

建议在 PDF 的“模型与参数信息”部分展示哈希前 12–16 位、训练波长范围和重采样状态。

### A6. 自定义模型基础校验

- 训练波长至少 2 个。
- 波长必须严格递增、无重复、处于合理范围。
- 导入时执行一次模拟输入试推理。
- 检查输出为单值序列、无 NaN/Inf、可转换为 `(N,)`。
- 输出数量与输入样本数量一致。
- 增加“仅导入可信来源 `.pkl/.joblib`”确认。

## 4. Phase B：影像头文件自动解析

### B1. 建立统一元数据结果结构

建议新增或规范字段：

```text
sensor_name
sensor_type
acquisition_datetime
flight_date
field_id
image_type
value_type
processing_level
wavelengths
bandwidths
wavelength_unit
band_names
metadata_sources
metadata_confidence
raw_metadata
```

每个字段应支持来源标记：

- `envi_header`
- `geotiff_tags`
- `band_tags`
- `xmp_sidecar`
- `aux_xml`
- `json_sidecar`
- `filename_rule`
- `user`
- `default`

### B2. ENVI 头文件增强

- 支持 BOM、UTF-8、GBK/ANSI 编码回退。
- 保持对 `.hdr`、`.HDR`、`.dat.hdr` 的兼容。
- 扩充常见键名别名并统一大小写、空格和下划线。
- 从 `band names` 或波段描述中提取 `475nm`、`B6 560nm`、`560 nm` 等中心波长。
- 自动读取传感器、采集日期/时间、数据级别和值类型等可选字段。
- 保存原始键值，便于追溯和问题排查。

### B3. GeoTIFF 标签增强

- 继续支持数据集级与单波段标签。
- 自动映射常见的 `sensor`、`instrument`、`acquisition_date`、`datetime`、`field_id` 等标签。
- 示例 GeoTIFF 中已有的 `sensor="DEMO"` 应能映射到平台传感器字段。
- 不覆盖 `user` 来源字段。

### B4. 伴随文件

最低实现：

- 支持 `.aux.xml` 中的基础 TIFF 元数据。
- 至少支持一种真实无人机传感器侧车格式，优先 MicaSense XMP。
- 支持通用 `.json` 元数据文件。

如果真实 XMP 样例不存在，必须用结构真实且脱敏的小型测试样例验证；不能只用空壳文件。

### B5. 文件名推断

- 支持从形如 `田块A_20260610_多光谱.tif` 推断田块和日期。
- 推断结果标记 `filename_rule`，置信度应低于头文件正式字段。
- 可以推断“多光谱/高光谱”类别，但不要凭空推断具体相机品牌。

### B6. 前端确认流程

- 每个字段显示“已识别、文件名推断、待人工确认、用户已修改”的来源状态。
- 提供“重新解析头文件”按钮。
- 重新解析前展示新旧值对比。
- 用户已修改字段默认保留，不静默覆盖。
- 页面文案不得再笼统写成“只能手工填写”。

## 5. Phase C：新增内置 DNN 模型

### C1. 最低交付

至少新增一个真正可推理的 DNN/MLP 内置模型：

- 建议 ID：`dnn_nmass_demo`
- 输入：400–900 nm、10 nm 步长、51 波段
- 输出：Nmass，`mg/g`
- 建议结构：标准化 + 两层或多层全连接隐藏层
- 推荐优先使用 scikit-learn `MLPRegressor`，避免新增大型运行时依赖
- 保存为 `.pkl/.joblib` 并生成完整 JSON 元数据

### C2. 推荐增强

在依赖可控的前提下再增加：

1. 五波段 DNN/MLP 模型，输入 475/560/668/717/840 nm。
2. 1D-CNN 光谱模型，优先导出为单输入 `(N,51)` 的 ONNX，继续复用当前 `onnxruntime`，不要求在运行态安装 PyTorch。

不允许为了增加模型数量把训练集指标冒充独立验证指标。

### C3. 模型元数据

每个新增模型必须包含：

- 唯一 ID、名称、版本
- 算法和模型结构说明
- 训练数据、样本数、数据是否合成
- 训练集和验证集划分
- 独立测试指标或统一标记为示例指标
- `R²`、`RMSE`、单位
- 输入波长
- 默认分级阈值
- 适用作物、传感器和限制说明

### C4. 验证

- 生成模型后启动实际推理，至少对一幅多光谱和一幅高光谱示例影像验证。
- 比较 DNN 与其他模型在均值、空间分布和分级占比上的合理性。
- 若结果明显失真，应调整训练或标注模型为限定用途，不得只修改显示指标。
- 结果页和 PDF 中的模型卡片必须显示真实模型名称，不得统一写成旧模型名。
